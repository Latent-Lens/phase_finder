# Authoritative model-result contract

PhaseFinder has one authoritative model result: the normalized object selected by `state.modeling.activeResultKey` from `state.modeling.resultsByKey`. Plot overlays, table fractions, exports, sessions, and fit-change events consume only that object. Required fields are `schemaVersion`, `modelId`, `modelVersion`, `expectedCounts`, `components`, `phaseFractions`, `diagnostics`, `warnings`, and `provenance`.

The older numbered pipeline that used to produce `peaks`, `baseFit`, `extendedFit`, and `report` in stages 5–8 is gone. `5ac4956` deleted `apply_base_fit`, `apply_contamination_fit`, and `apply_fit_report` along with their numerical adapters — `legacy_bridge_fit.js`, `debris_aggregate_extension.js`, `cell_cycle_fit_report.js`, and `models/legacy_bridge.js` — and the whole 21-file `js/analysis/djf/` directory. `apply_peak_detection` (stage 0-4, canonical) is unaffected. The three retired slot names still sit in `STATE_FIELDS_IN_ORDER` (`pipeline_state.js:117`), initialised to `null` and never written; nothing outside `pipeline_state.js` itself reads them.

`legacy_bridge_v1` no longer exists as a registry model. `unit_tests_cell_cycle_registry.py:88` asserts `registry.get_model('legacy_bridge_v1') === null` and that the id is absent from the registered list. There is now only one modeling path: the canonical result stored in `resultsByKey` under the authority rule above. No persisted session field depends on `baseFit`, `extendedFit`, or `report`, so their retirement required no session migration.
